# Contributing to BioSensus

BioSensus is in **Frontend Prototype / Early Development**. Contributions can be proposed through GitHub issues and pull requests by people who have repository access. No project license has yet been selected; contact the owner about permission and contribution terms before submitting material for reuse.

## Propose a change

1. Review the README, known limitations, and roadmap.
2. Open an issue describing the problem or proposal, expected behavior, and relevant screenshots or reproducible steps. Do not include passwords, tokens, private farm information, or other sensitive data.
3. Discuss scope with the project owner before substantial implementation.
4. Create a focused development branch from `main` when a change is approved.
5. Open a pull request explaining what changed, why, and how it was checked. Identify data sources, dependencies, and assumptions where relevant.

Documentation improvements, interface changes, integrations, and analytical models must be described accurately. Do not present mock data as live measurements or unvalidated outputs as agronomic guidance.

## Review expectations

- Preserve the initial publication in Git history.
- Keep changes focused and avoid unrelated formatting or dependency upgrades.
- Provide validation appropriate to the proposed change; this initial publication does not include an automated test suite.
- Update documentation and changelog when behavior or version status changes.
- Obtain owner review before merging into `main`.

No contributor branches, release automation, branch protection rules, or CI checks are created by this publication. See [versioning guidance](docs/versions.md).
